I Hate Documenting Environment Settings, So I Let Copilot Cowork Do It

Nov 12, 2026 · Chad Cox

I had Copilot Cowork read the Entra admin center and write a configuration runbook: every setting, the PowerShell that sets it, and how it compares to CISA, CIS, NIST and Zero Trust guidance. Then I scheduled it to email me when something drifts.

Short version

  1. Activate Global Reader (through PIM if you use it).
  2. Open Copilot Cowork in the browser and paste the prompt below. Swap in the admin center you want, and keep "do not make any setting changes".
  3. Review the Gap and Review items. Write down why you accept any deviation.
  4. Save the document to a team SharePoint library.
  5. Schedule a monthly re-run with the drift email.

Why I did this

I hate writing documentation. I like building and fixing things, not screenshotting an admin center into a Word table. Keeping it current is worse. Someone adds a Conditional Access policy or a new admin, and nobody trusts the document anymore.

So I handed it to Cowork. It works for any settings page you can open in Edge: Microsoft 365, the Azure portal, Power BI or a third-party SaaS console you're signed in to.

Before you start

Cowork reads the admin center through Microsoft Edge on your device, signed in as you. It can't see anything you can't.

  • License and access. A Microsoft 365 Copilot license and Cowork enabled in your tenant.
  • Browser access turned on. It's off by default. Copilot > Settings > View all > Cowork settings > Allow browser access. You can scope it to your admin group.
  • Cowork in a browser, plus Edge. Browser tasks don't work in the desktop app or on mobile. Edge must be signed in with the same work account (no InPrivate or guest windows). If you manage Edge, the CopilotCoworkToolActionsEnabled policy must allow it.
  • A read-only role, activated. Global Reader covers almost everything. See the least-privilege section.
  • You nearby. Conditional Access and MFA still apply, and Cowork hands control back for sign-in prompts.

Every Cowork browser task is recorded in the unified audit log.

The prompt

Log into the Entra admin portal and write up a document about every setting that is currently set. Write it as a tech document that’s easy for peers to follow to set up another environment. Call out any setting that doesn’t follow best practices like CISA, CIS, NIST and Microsoft, including Zero Trust. This is documentation only. Do not make any setting changes. For each setting, include the PowerShell cmdlet that can be used to set it.

Cowork opened the Entra admin center with my existing session and went blade by blade. It only read pages, never clicked Save, and built the Word document in my OneDrive.

What came back

19 sections and 114 settings from my lab tenant. Each setting has its current value, a status, the baseline it was checked against, and the PowerShell to set it. It covered tenant properties, user and guest settings, groups, devices and app consent, Conditional Access (all 57 policies plus named locations), authentication methods, password reset, ID Protection, admin roles and hybrid identity.

The PowerShell column turns it into a runbook for the next tenant. For example, Update-MgPolicyAuthorizationPolicy for user and guest settings and New-MgIdentityConditionalAccessPolicy for Conditional Access.

Each setting gets a status

Status What it means
Aligned Matches the recommended baseline
Gap Doesn’t follow one or more baselines and should be fixed
Review Depends on your environment. Decide on purpose and record why.
Info No baseline applies

It checks against the CISA SCuBA (Secure Cloud Business Applications) baselines, the CIS Microsoft 365 Foundations Benchmark, NIST SP 800-63B, 800-207 and 800-53, Microsoft Zero Trust and Conditional Access guidance, Microsoft security baselines and Secure Score, and the CIS Windows and Intune benchmarks.

Mine came out to 40 Gap, 31 Review, 24 Aligned and 19 Info, with a remediation order. Examples:

  • Most Conditional Access policies were still report-only, so they weren’t enforcing anything.
  • There were far more Global Administrators than the “fewer than five” Microsoft recommends.
  • Self-service password reset was off.
  • Entra sign-in and audit logs weren’t sent anywhere for long-term retention.

This is evidence. When audit, compliance or cyber insurance asks how identity is configured against a recognized framework, you hand over a dated document. The Review items are where you record why you deviated, which is what auditors want to see.

Note: The baseline mapping is a starting point, not a certified audit. Have your security team check it against the benchmark versions you follow.

Where there's no cmdlet, the document should say “portal only” with the navigation path. CISA’s ScubaGear and Microsoft365DSC pair well with this: Cowork can turn their output into a document people will read.

Guardrails (add to every prompt)

This is documentation only: do not change, save or create anything in the portal. For every setting, give the current value; whether it is Aligned, Gap, Review or Info against CISA SCuBA, the CIS Microsoft 365 Foundations Benchmark, NIST and Microsoft Zero Trust guidance; and the PowerShell cmdlet that sets it (or “portal only” with the navigation path). Write it as a Word document a peer could follow to rebuild the configuration, and save it to my OneDrive.

Defender for Office 365

Open the Microsoft Defender portal and document every email and collaboration policy: preset security policies, anti-phishing, inbound and outbound anti-spam, anti-malware, Safe Links, Safe Attachments, quarantine policies and alert policies. Note which users and domains each policy applies to and which policy wins when they overlap.

Defender for Endpoint

Open the Microsoft Defender portal and document the endpoint settings: advanced features, device groups and remediation levels, automated investigation, attack surface reduction rules, tamper protection, EDR in block mode, indicators and onboarding status. Note which settings are delivered through Intune rather than the Defender portal.

Intune

Open the Intune admin center and document compliance policies, configuration profiles, endpoint security policies, security baselines, enrollment restrictions, Windows Autopilot profiles, Windows update rings, app protection policies and tenant administration settings. Include each policy’s assignments and exclusions.

Exchange Online

Open the Exchange admin center and document organization settings, mailbox auditing, remote domains and automatic forwarding, mail flow rules, connectors, accepted domains, DKIM, and the SPF and DMARC records for each accepted domain.

SharePoint and OneDrive

Open the SharePoint admin center and document external sharing for SharePoint and OneDrive, default link type and permissions, guest access expiry, access control (unmanaged devices, idle session sign-out, network location), OneDrive sync restrictions, site creation and storage settings.

Teams

Open the Teams admin center and document external access, guest access, Teams settings (email into channels, third-party file storage), meeting policies and meeting settings, messaging policies, and app permission and setup policies. Show the global (org-wide default) policy and every custom policy with who it is assigned to.

Microsoft Purview

Open the Microsoft Purview portal and document audit (on or off, and retention), retention policies and labels, data loss prevention policies, sensitivity labels and label policies, and any insider risk or communication compliance policies. Note the scope and mode (test or enforced) of each policy.

Power Platform

Open the Power Platform admin center and document the environments (type, region, security group), data policies (DLP) and their connector groups, tenant settings such as who can create environments and trials, tenant isolation, and Copilot and AI settings.

Microsoft 365 admin center

Open the Microsoft 365 admin center and document the org settings: password expiration policy, idle session timeout, release preferences, Customer Lockbox, user-owned apps and services, Microsoft 365 on the web, calendar and Bookings sharing, and Copilot settings. Mark anything that can only be set in the portal.

Least privilege: use Global Reader

I ran my first pass as Global Administrator because that's how I was signed in. Nothing here changes a setting, so Global Reader is the right role. It reads settings across Microsoft 365 without management actions: Entra, Defender, Intune, Exchange, SharePoint, Teams and most of Purview.

What you’re documenting Least privilege needed
Entra ID Global Reader. Security Reader if you only need Conditional Access and ID Protection.
Exchange Online, SharePoint and OneDrive, Teams, Microsoft 365 admin center Global Reader
Defender XDR and Defender for Office 365 Global Reader or Security Reader
Intune Global Reader or Intune Read Only Operator
Microsoft Purview Global Reader for most pages. Some need a view-only Purview role group.
Power Platform Test Global Reader first. Some settings may need Power Platform Administrator or an environment role.
Diagnostic settings destination (Log Analytics workspace or storage) Add Reader on the Azure subscription
Scripted run through Microsoft Graph Application permissions: Policy.Read.All, Directory.Read.All, RoleManagement.Read.Directory, Organization.Read.All
  • Activate it with PIM. Make Global Reader eligible and activate it per run. Don’t keep it standing.
  • Some values are hidden. Group lifetime and smart lockout thresholds were hidden even for Global Administrator. The document marks them “masked” instead of guessing.
  • Do one test run. Confirm Global Reader can see every blade your tenant uses.
  • Know the gaps. Microsoft lists a few places Global Reader can’t see yet. Power Platform is the most likely. Check the current list.

Keep it current: schedule it and email the drift

Ask Cowork to run on a schedule, for example: “On the first Monday of every month, capture the configuration baseline for Entra ID, Defender, Intune, Exchange Online, SharePoint and Teams, one document per workload, and save them to my OneDrive.”

Save the runs to a SharePoint library your team owns, with versioning on, so the history survives role changes. Then add this to the scheduled prompt:

Compare this run with the previous version in my OneDrive (or SharePoint) folder. If any setting changed, a policy was added or removed, or a status moved from Aligned to Gap, email me a summary of the differences. If nothing changed, send a one-line “no drift” email.

Now you get a short email like “Conditional Access policy X was switched from Report-only to On” or “two new Global Administrators were added since last month.” Unplanned changes show up within a month instead of at the next audit, and the version history becomes a dated record of your security posture.

I still hate writing documentation. Now I don’t have to.
