Locking Down Copilot Connectors Without Breaking Anything

Nov 12, 2026 · Chad Cox

Measure usage, put a group boundary around Copilot tools, assign what's approved and block the rest. The Graph API covers inventory and blocking. Group access is still done in the admin center.

Short version

  1. Pull the Connectors and Agents usage reports (Reports > Usage > Microsoft Copilot).
  2. Set Agents > Settings > User access to your security groups.
  3. Assign each approved tool to the groups that need it.
  4. Block the MCP servers you never want.
  5. Work the Requests queue (Agents > Tools > Requests) from then on.

Why: everything is on by default

In one tenant I reviewed, the Tools registry had 470 plugins and 458 MCP servers, and the Copilot Connectors page had dozens of third-party connections in a Ready state. Most were set to "All users". Nobody had approved them one by one.

There's no block-all button, and blocking blindly cuts people off from tools they use. Measure first, keep what's needed, restrict the rest to groups.

The four steps

1. Measure before you change anything

Under Reports > Usage > Microsoft Copilot, the Connectors report shows connections used by Copilot and agents, active users and responses over 7 or 30 days. The Agents report shows active users and agents. In our review every number was zero, so restricting access wouldn't interrupt anyone.

Be careful with zero. The Connectors report is in preview, only looks back 30 days and doesn't count Cowork usage yet. Zero means "no recent measured use", not "never needed".

2. Set the outer boundary with groups

Agents > Settings > User access decides who can use any agent or plugin at all. Change it from "All users" to "Specific users or groups". Everything else sits inside this setting. We used six groups: SuperUsers plus Revenue, Finance, People, Technology and Operations.

Check group membership before you save. Anyone outside the groups loses access right away.

3. Assign approved tools to groups

Each plugin under Agents > Tools has a Users tab: All users, No users, or Specific users and groups. Copilot connections have an "Add staging" option that does the same thing. Give SuperUsers every approved item, then add the department that needs it.

Leave "No users" items alone. Switching them to a group turns them on.

4. Block what you never want

Blocking an MCP server under Agents > Tools > MCP servers also blocks its linked plugins and connectors. The confirmation dialog lists them. We blocked Google Drive, Google Calendar, Google Sheets, Google Tasks and Google Contacts this way.

There was no item called "Google Docs". Docs files are reached through Google Drive. Check what a name covers before assuming it's missing.

Users can still see restricted plugins and choose Request access. Those requests land in Agents > Tools > Requests, which becomes your approval queue.

What you can automate

The Agent 365 Package Management API in Microsoft Graph treats each agent, plugin, MCP server or skill as a "package". Inventory and blocking can be scripted:

Operation Endpoint Status
List packages GET /copilot/admin/catalog/packages Available
Get package details GET /copilot/admin/catalog/packages/{id} Available
Update package metadata PATCH /copilot/admin/catalog/packages/{id} Preview
Block a package POST /copilot/admin/catalog/packages/{id}/block Preview
Unblock a package POST /copilot/admin/catalog/packages/{id}/unblock Preview
Reassign ownership POST /copilot/admin/catalog/packages/{id}/reassign Preview

Where the API falls short

  • Block, unblock, update and reassign are in preview. They can change before general availability.
  • It needs a Microsoft Agent 365 license and the AI Administrator role.
  • Listing packages returns only items that contain an agent by default. Filter on element type to see plugins, MCP servers and skills.
  • Power Platform connectors aren't returned.
  • There's no endpoint for the org-wide User access setting, the publisher categories, per-plugin group assignment or connector staged rollout. Those were the core of our approach, so they're still done in the admin center.

Bottom line: the API tells you what you have and turns items off. It can't say "only these groups may use this tool" yet, and that's where most of the governance value is.

Permissions (least privilege)

You don't need Global Administrator. AI Administrator covers Copilot settings, agents, plugins, MCP servers, skills, usage reports and most tenant-wide consent. Microsoft is still expanding the role, so test each step with it before assuming you need more. Assign it through Privileged Identity Management (PIM) and activate it only for the session.

Task Least-privileged role
Usage reports, User access, plugin group assignment, blocking, MCP server approvals AI Administrator
Consent for apps that need Microsoft Graph application permissions Global Administrator or Privileged Role Administrator
Create the SG-Copilot groups and manage membership Groups Administrator (group owners can maintain membership day to day)
Read-only review AI Reader or Global Reader. Reports Reader if you only need the usage report APIs.
Search the audit log for Copilot and Cowork activity Audit Reader (Microsoft Purview)
Script inventory or blocking with the Package Management API AI Administrator plus an Agent 365 license. CopilotPackages.Read.All to inventory, CopilotPackages.ReadWrite.All to block (one-time admin consent).

Let Cowork do the clicking

Where the API stops, Cowork can work the admin center for you. It reads the usage reports, walks the Tools registry, applies group assignments, confirms each "updated successfully" message and writes a report as it goes. It's slower than an API call and should pause before anything that blocks or broadens access. It still saves hours of clicking.

What Cowork needs

Cowork drives Microsoft Edge on your device, signed in as you. It can't do anything you can't.

  • License and access. A Microsoft 365 Copilot license and Cowork enabled in your tenant, including the Anthropic subprocessor setting where your region requires it.
  • Browser access turned on. It's off by default. Copilot > Settings > View all > Cowork settings > Allow browser access. Scope it to your admin group.
  • Cowork in a browser, plus Edge. Browser tasks don't work in the desktop app or on mobile. Edge 152.0.4191.53 or later, signed in with the same work account (no InPrivate or guest windows). If you manage Edge, enable the CopilotCoworkToolActionsEnabled policy.
  • Role activated in PIM. AI Administrator, plus Groups Administrator if the session will touch membership. If Cowork hits a permission error, it should stop and tell you.
  • You nearby. Select I understand the first time Cowork needs the browser. Conditional Access and MFA still apply, and Cowork hands control back for sign-in prompts.

Every change is attributed to your account, and each Cowork browser task is in the unified audit log.

Sample prompt

Copy and adapt this prompt:

Open the Microsoft 365 admin center and help me move Copilot agents, plugins, MCP servers, skills and connectors to an approved-only model. I am signed in with the AI Administrator role activated; if any page says I lack permission, stop and tell me rather than trying another way. Do this in order and pause for my approval before any change:

  1. Read-only: pull the Copilot Connectors and Agents usage reports for the last 30 days and list every plugin, MCP server, skill and Copilot connection with its current status and who it is available to. Save this as a spreadsheet.

  2. Set Agents > Settings > User access to Specific users or groups using these groups: SG-Copilot-SuperUsers, SG-Copilot-Revenue-Bronze, SG-Copilot-Finance-Bronze, SG-Copilot-People-Bronze, SG-Copilot-Technology-Bronze and SG-Copilot-Operations-Bronze.

  3. For every item that is currently Available, change it from All users to SG-Copilot-SuperUsers plus the department group I assign in the spreadsheet. Do not turn on anything that is currently set to No users or Not available.

  4. Block these MCP servers for the whole organization: [list items, for example Google Drive MCP, Google Calendar]. Show me the linked plugins and connectors before confirming each block.

  5. After each change, confirm the success message on screen. Keep a Word report of every action with the previous and new setting, and list anything you could not change.

What makes it work: say what must stay off, ask for a read-only inventory first, and ask for before-and-after values. That report is the fastest way to undo a single change.
